# 基于 Spark 的社区健康管理系统

> AI 健康风险评估 · Spark + ECharts 多维健康数据分析 · 居民健康档案与指标自助记录 · 医生排班预约与服务留痕 · 定时异常指标预警

起因挺实在：社区卫生服务站每年给居民做体检，量完血压血糖记在纸质表上，回头再录进 Excel；等要做"本社区高血压人群有多少、哪几个老人最近指标不对劲"这种统计，就得翻表翻到眼花，慢病随访更是靠医生自己记。

这套系统就是冲着这个场景做的：**把居民档案、健康指标、生活行为、预警、预约、服务记录全部落到平台上，再交给 Spark 做聚合分析**。做毕设答辩时，"Spark 在哪个环节真正起作用"和"预警是怎么算出来的"这两段特别有讲头，比单纯写增删改查扎实。

## 一、项目简介

基于 Spark 的社区健康管理系统采用前后端分离的 B/S 架构，由居民服务端和管理员、社区医生共用的管理端组成。系统以系统账号、居民、医生、健康档案、健康指标、生活行为、健康预警、健康风险评估、医生排班、预约、服务项目、服务记录、健康知识及用户反馈为核心业务数据，覆盖居民建档、健康记录、异常预警、预约就诊、服务留痕、健康科普与数据分析等场景。居民可自助维护个人健康信息、在线预约和查看健康预警；社区医生可维护居民档案、排班、预约与服务记录；管理员可维护平台基础数据并查看社区整体健康与服务运营情况。

## 五、核心实现

### 5.1 三角色账号体系、JWT 认证与端侧划分

系统将账号分为管理员、社区医生和居民三类角色。账号登录后，服务端在 JWT 中写入用户 ID 和角色信息；后续请求由拦截器解析令牌，并将当前用户保存到线程上下文。前端保存登录状态和用户信息，通过路由守卫限制居民进入管理端，管理员和社区医生进入后台工作区，业务数据也按角色范围组织。

### 5.2 居民档案、医生资料与健康信息建档

居民资料以系统账号为身份基础，保存姓名、联系方式、性别、出生日期、住址、医保等信息；医生资料关联系统账号，保存所属科室、职称、擅长方向和联系方式。健康档案围绕居民建立，记录血型、过敏史、既往病史、慢性病、家族病史、残疾情况和用药信息。后台提供分页查询、新增、编辑、删除以及 Excel 导入导出能力；居民端仅围绕当前账号关联的个人资料和健康档案进行查看或维护。

### 5.3 健康指标记录、BMI 计算与历史追踪

健康指标模块记录居民在不同时间的身高、体重、收缩压、舒张压、心率、空腹血糖、餐后血糖、血脂、体温和血氧饱和度等数据。录入或修改身高、体重后，系统按体重除以身高平方米计算 BMI 并随记录保存。社区医生可在后台按居民维护和查询指标，居民也可在前台填写本人数据并查看历史记录。各次指标记录均关联居民和记录时间，为异常扫描、风险评估及社区指标分析提供连续数据来源。

### 5.4 定时指标扫描、健康预警生成与处理

系统通过定时任务扫描健康指标记录，对血压、空腹及餐后血糖、BMI、心率、血脂、体温和血氧饱和度等数值进行阈值判断。检测到异常时，根据异常程度生成提醒、警告或严重级别的健康预警，并记录关联居民、来源指标、异常项目、实测值、正常范围、预警说明及预警时间。生成预警前会检查该指标记录是否已经产生过预警，避免重复创建。居民可在前台查看本人预警并标记已处理，医生或管理人员可在后台查询预警、维护处理说明和处理状态。

### 5.5 生活行为记录与 AI 健康风险评估

生活行为模块记录吸烟、饮酒、运动频率、运动方式、饮食习惯、盐摄入、睡眠质量和心理状态等健康相关行为。健康风险评估模块结合居民健康档案、最新健康指标和生活行为信息构建评估上下文，调用 DeepSeek API 生成风险等级、风险因素分析与健康建议，生成后的评估报告与居民关联保存。系统默认复用五小时内的最近评估结果，用户也可主动请求刷新，兼顾响应速度与数据时效。

### 5.6 医生排班、在线预约与服务记录留痕

医生排班模块按医生、日期和时段维护可预约时间，居民端在医生详情中查看医生资料及排班情况，选择服务类型、预约日期和时段后提交预约。预约记录保存居民、医生、服务类型、预约时间、状态及服务小结等信息，并在"待确认、已确认、已完成、已取消"等状态之间流转。社区医生可查看本人预约并执行确认、完成或取消操作，居民可查看并取消符合条件的本人预约。完成服务后，后台为居民登记服务项目和服务记录，保存服务医生、服务时间、服务内容和满意度。

### 5.7 健康知识浏览与居民反馈处理

健康知识模块由后台维护科普文章标题、分类、封面、摘要、正文、发布状态和浏览量等信息。居民端展示已发布的健康知识列表并支持查看详情，打开详情时系统增加对应文章浏览量。居民也可通过前台提交意见或问题反馈，反馈记录保存反馈内容、提交人、处理状态、处理说明和处理时间。管理员或社区医生可在后台查看反馈列表并维护处理进度。

### 5.8 Spark SQL 数据看板与社区健康概览

系统以 SparkSession 为统计计算入口，在本地模式加载 MySQL 中的居民、健康档案、健康指标、风险评估和预约等数据表，注册为临时视图后使用 Spark SQL 完成聚合分析。管理端首页展示居民总数、慢病人数、今日预约数和待处理预警数等核心数据；同时通过 ECharts 呈现居民年龄段分布、性别分布、慢性病分布和健康风险等级分布。图表数据由服务端统一返回，前端根据维度数据渲染柱状图和饼图。

### 5.9 预约、服务、健康指标与医生工作量分析

除首页总览外，系统提供预约数据分析、服务项目分析、健康指标分析和医生工作量统计页面。预约分析围绕月度预约量、已完成与已取消数量、热门医生、预约时段和服务类型展开；服务分析统计服务项目启用情况、月度服务量、服务热度排行、满意度和趋势；健康指标分析展示血压、血糖、BMI 分布、异常率及指标变化趋势；医生工作量统计汇总医生预约完成量、服务次数、满意度、月度趋势及综合工作量排行。各分析模块使用 Spark SQL 完成数据聚合，再由 ECharts 以折线图、柱状图、饼图等形式呈现。

### 5.10 社区健康管理业务全流程

系统以居民资料和健康档案为起点，持续沉淀健康指标和生活行为数据，以定时预警和 AI 风险评估识别健康关注事项，再通过医生排班、在线预约和服务记录支撑线下社区卫生服务。健康知识与居民反馈为日常健康教育和服务改进提供入口；居民、医生、预约、服务和指标等数据最终进入 Spark 分析模块，形成面向管理人员的社区健康与服务运营反馈。管理员负责基础数据和平台内容维护，社区医生承担健康服务和预警处置，居民完成自助记录与服务参与，共同构成可查询、可追溯、可分析的社区健康管理流程。
